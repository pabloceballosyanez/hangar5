# Modo Solo — Unified Order Dashboard for Hangar 5

> **Para Hermes:** Usar el skill `plan` para implementar. TDD donde aplique.

**Objetivo:** Crear una pantalla única (`/solo`) que combine toma de pedidos, visualización de cocina (KDS) y entrega en una sola vista. Para días de baja afluencia donde una sola persona hace todo.

**Arquitectura:** Nueva ruta `/solo` con layout vertical adaptado a mobile-first. Tres secciones colapsables en una sola página: (1) cola de cocina compacta, (2) sesiones/mesas abiertas, (3) detalle de sesión seleccionada con acciones rápidas. Menú de pedidos en bottom sheet. Sin cambios a las rutas existentes.

**Tech Stack:** Next.js 16, React 19, Tailwind 4, TypeScript. Reusa componentes y APIs existentes.

---

## El problema actual

En días de baja afluencia (entre semana), una sola persona debe saltar entre 3-4 pantallas:

| Pantalla | Acción |
|---|---|
| `/waiter/session/[id]/order` | Tomar pedido (menú + carrito) |
| `/kds` | Ver qué hay pendiente en cocina |
| `/waiter/session/[id]` | Marcar ítems como entregados |
| `/waiter/session/[id]` + sheet | Cobrar |

Esto es lento y confuso para una persona sola. El Modo Solo lo unifica todo.

### Flujo de uso (una persona)

1. Abre `/solo` en el celular/tablet
2. Ve la cola de cocina arriba → sabe qué está pendiente
3. Toca `[✓ LISTO]` en un ítem → se marca como READY
4. Si un cliente quiere ordenar:
   - Toca la mesa en "Mesas Abiertas" o "+ Nueva mesa"
   - Abre el menú → selecciona ítems → envía a cocina
5. Cuando algo está listo en cocina, aparece en el detalle de la sesión → toca `[🍽 Entregar]`
6. Para cobrar → toca `[💵 COBRAR]` → selecciona método

## Fase 1: Cola de cocina compacta + mark-ready

### Tarea 1: Componente `SoloKitchenQueue`

**Objetivo:** Versión compacta del KDS actual, optimizada para mobile. Cada orden es una tarjeta colapsada; expande al tocar para ver ítems y marcarlos listos.

**Files:**
- Crear: `src/components/SoloKitchenQueue.tsx`

**API:** `GET /api/admin/restaurant/kds` (existente)

**Diseño de tarjeta compacta:**
```
┌──────────────────────────────────┐
│ 🔴 M3  Hamburguesa ×2   12 min  │  ← Collapsed: mesa + resumen + tiempo
├──────────────────────────────────┤
│ 2x Hamburguesa    [✓ LISTO]      │  ← Expanded: ítems individuales
│ 1x Papas fritas   [✓ LISTO]      │     con botón mark-ready
│ 📝 sin cebolla                    │
└──────────────────────────────────┘
```

**Estados visuales:**
- `urgency=low` (<15 min): borde verde, sin pulso
- `urgency=medium` (15-30 min): borde ámbar
- `urgency=high` (>30 min): borde rojo, pulso

**Mark-ready:** PUT a `/api/admin/restaurant/orders/[orderId]/items/[itemId]/status` con `{status: "READY"}`. Feedback optimista (actualizar UI antes de que responda el server).

**Auto-refresh:** `setInterval` cada 15 segundos, como el KDS actual.

## Consideraciones de UX

### Para mobile (viewport estrecho)
- Las tarjetas de cocina son full-width, una debajo de otra
- El grid de sesiones usa 2-3 columnas con scroll horizontal
- El detalle de sesión ocupa todo el ancho
- El menú es un bottom sheet que cubre el 85%

### Para tablet/desktop
- Opcional: layout de 2 columnas (cocina + sesiones a la izquierda, detalle a la derecha)
- Menú en panel lateral en vez de bottom sheet
- **Pero NO es prioridad.** Mobile-first. Si funciona en celular, funciona en tablet.

### Transiciones
- Las tarjetas de cocina colapsan/expanden con animación suave
- El menú sheet se desliza desde abajo
- Mark-ready tiene feedback háptico (si el dispositivo soporta) + optimista

### Sonido (opcional, para futuro)
- "¡Orden lista!" cuando todos los ítems de una orden pasan a READY
- "¡Nueva orden!" cuando entra una orden desde QR
- **No en esta fase.** Dejarlo para después.

## Riesgos y mitigaciones

| Riesgo | Mitigación |
|---|---|
| Muchas llamadas API en una sola página | Agrupar en endpoint `/api/solo/state` si hay problemas de rendimiento. Mientras tanto, llamadas paralelas con Promise.all. |
| Estado desincronizado entre componentes | Auto-refresh cada 15s en cocina, 30s en sesiones. Refrescar al volver de menú sheet. |
| Scroll infinito en mobile | Cada sección colapsable. Solo una sección expandida a la vez (acordeón). |
| Conflictos con sesiones existentes | Sin cambios en `/waiter/*` ni `/kds`. Modo Solo es una vista adicional, no un reemplazo. |
